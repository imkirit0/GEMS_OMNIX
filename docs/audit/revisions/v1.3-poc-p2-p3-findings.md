# Revision v1.3: findings from POC P2/P3, local run (2026-10-27)

**Trigger:** E-008. These corrections are **PRO** (technical). None changes a business rule, and none approves NP-1…8.

| C-ID | Affects | Finding (evidence) | Change |
|---|---|---|---|
| C-18 | 06 §3 RLS; T-RLS-004 | A materialized view cannot carry RLS. A `security_invoker` view over it needs the invoker to hold SELECT on the matview, and that SELECT exposes every centre. The 06 wording "only through filtered security-invoker views" therefore cannot be met safely | Pre-aggregates are **plain tables with RLS**, refreshed by `gems_job`. Matviews are never granted to app roles. T-RLS-004 asserts both (E-008) |
| C-19 | 06 §3; data model | Foreign-key (RI) checks bypass RLS. A single-column FK lets a centre-A row reference a centre-B row (an existence oracle, and a cross-tenant link) | Every reference between tenant tables uses a **composite FK** `(centre_id, x_id) → (centre_id, id)`. Asserted inside T-RLS-008. PROPOSED new ID **T-RLS-019** "composite-FK coverage" (not yet in the matrix) |
| C-20 | T-RLS-017 threshold | Measured +28% / +46% p95 on sub-millisecond queries. The absolute cost is ≈0.2–0.25 ms per statement: one InitPlan evaluation of the scope function, with the index still used. A relative threshold is dominated by query size | Replace "≤ 10%" with **absolute added p95 ≤ X ms per statement** (X PROPOSED 2 ms, owner: architecture), measured on Supabase at production size. Optional optimisation (cache the scope per transaction) only if the Supabase run fails |
| C-21 | 09 tool table | The POC uses `node:test` (stdlib) instead of Vitest, to avoid a dependency for throwaway code | POC-only deviation. Stage-2 code follows 09 unless revised |
| C-22 | 11 environment | The Supabase Postgres major version is unverified (E-008). The local run uses 17.11 | Read `select version()` on Supabase before the C-17 re-run. If the major differs, repeat the local run on that major |
| C-23 | 06 Audit | `audit_log` append-only is enforced by grants plus triggers. `gems_owner` can still disable the triggers | Expected: the owner role is migration-only and never used at runtime. Re-check under T-AUD-* in P4 (optional hash chain, D-FIN-8) |

**Unchanged:** NP-3 remains PMC. P3 proved one mechanism serves both modes. It did not pick one.
