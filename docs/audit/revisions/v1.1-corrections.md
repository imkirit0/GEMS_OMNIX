### C-02.2 Mechanism (PRO; must support every policy option)
- One `number_series` row per (series key per NP-1, period per NP-2).
- Allocation runs `UPDATE … SET current = current + 1 … RETURNING` **inside the caller's business transaction**. The row lock serialises allocators, and a rollback releases the increment, which gives gapless capability.
- A unique index on (series, period, number) is the final guard.
- With NP-3 = unique-only, the same code still applies (no Postgres SEQUENCE, so one mechanism serves both policies).
- Formatting is a pure function of the policy config (NP-5), unit-tested.

| ID | Test | Expected (gapless mode) | Expected (unique-only mode) | Failure condition |

## C-03 Entity-aware migration reconciliation

**Replaces** "record counts per entity (source vs target vs exceptions)" (v0 §7.4) and the single disposition sentence in A.7.

### C-03.1 Dispositions (every source key gets exactly one; enforced by a unique constraint on the source key)
| Disposition | Meaning | Target effect | Requires |
|---|---|---|---|
| IMPORTED | 1 source → 1 target | one target row | rule id |
| MERGED | n sources → 1 survivor (e.g. duplicate religions, duplicate persons) | survivor row; the others point to it | approved merge rule + survivor id |
| SPLIT | 1 source → n targets (e.g. an XLS enrolment row → person + course registration + fee plan; a legacy combined field) | n target rows, all linked to the source key | split rule |
| ARCHIVED | kept read-only outside the active model (e.g. logs older than the retention cut, legacy school-ERP data) | row in the `archive` schema with the source payload | approved archive rule |
| EXCLUDED | intentionally not migrated (e.g. test centres GDEMO, KL-01-TEST3, KL-01-TEST6) | none | **approved exclusion reason + approver** |
| REJECTED | failed validation (e.g. XL-4 corrupted cells, orphan FK) | none until fixed | exception reason; **must be 0 at cutover**, each one fixed, re-run, or re-classified to EXCLUDED with approval |

### C-03.2 Traceability tables
- `migration.key_map(run_id, source_system, source_table, source_key, source_row_hash, disposition, rule_id, target_table, target_id, survivor_target_id, reason, approved_by, approved_at)`. MERGED and SPLIT produce one row per (source, target) pair.
- `migration.rule(rule_id, entity, description, disposition, owner, approved_by, approved_at, version)`. A rule without approval cannot run in a cutover-mode execution.
- `migration.exception(run_id, source_key, rule_id, field, value_fingerprint, message)`. Fingerprints, not raw PII.

### C-03.3 Reconciliation checks per entity and run (all must pass; results stored in `migration.reconciliation`)
| Check | Formula | Scope |
|---|---|---|
| K1 Source coverage | count(source keys) = count(distinct source keys in key_map) | per entity, per centre, per year |
| K2 Disposition balance | source = IMPORTED + MERGED(sources) + SPLIT(sources) + ARCHIVED + EXCLUDED + REJECTED | per entity, per centre, per year |
| K3 Target provenance | every active target row has ≥ 1 key_map row (or is a documented system seed) | per target table |
| K4 Merge integrity | each MERGED group has exactly one survivor; the survivor exists; no chains | per entity |
| K5 Split integrity | each SPLIT source yields the expected target set (rule-defined cardinality) | per rule |
| K6 Referential integrity | 0 orphan FKs in target; source orphans appear as REJECTED/EXCLUDED with a reason | all FKs |
| K7 Amount control totals | Σ source amounts = Σ target amounts + Σ EXCLUDED/ARCHIVED amounts (reported separately with reasons), per centre / FY / fee head / account | all money tables |
| K8 Ledger | per FY: target trial balance nets to 0; **legacy imbalances reported, never auto-balanced** (treatment per D-MIG-3, approved by Accounts) | journals |
| K9 Determinism | two runs on identical input produce identical key_map (same target ids via deterministic keys) and identical totals | whole run |
| K10 Report parity | the 16 admission reports + key fee reports equal legacy values for sampled periods; differences explained per rule | reports |
| K11 Sampled field fidelity | random stratified sample (e.g. 0.5% per centre, min 20) compared field-by-field after transforms | per entity |

**Exit:** K1–K11 green, REJECTED = 0, every EXCLUDED/ARCHIVED rule approved, and the sign-off recorded in the evidence log. P8 (A.8) is amended to assert K1–K9 on the synthetic dataset.

## C-05 Authentication: one implementation, chosen by ADR

**Replaces** v0 §4.1's "Better Auth … Fallback … first-party module" (two competing implementations).

**ADR-001 Authentication implementation**, status **Proposed**.
- **Candidates:**
  - (A) Better Auth with DB sessions + TOTP plugin.
  - (B) First-party module: argon2id + otplib TOTP + opaque DB sessions.
  - (C) Auth.js. Excluded only if its Credentials provider is confirmed JWT-only; DR-14 says to verify this in the POC, not assume it.
- **Method:** time-boxed POC (≤ 3 days). The **same** test suite T-AUTH-001…020 (C-08) is run against each candidate in a throwaway branch.
- **Mandatory criteria** (all must pass):
  - DB-backed sessions with immediate revocation;
  - TOTP enforced for HO roles;
  - step-up re-auth with a timestamp;
  - session rotation;
  - lockout and rate-limit hooks;
  - audit hooks inside the same tx;
  - works with Next.js App Router server actions and route handlers;
  - argon2id (or a documented equivalent) with a legacy-password rehash path (D-MIG-6).
- **Scored criteria:** code + dependency surface, maintenance activity, migration fit, test effort.
- **Decision rule:** among candidates passing every mandatory test, choose the smallest surface (fewer dependencies and lines of own security code). Ties go to the candidate needing less first-party crypto/session code.
- **After approval:** the losing candidates' code is deleted from the POC. ADR-001 is marked Accepted with test evidence, and every document references only the chosen implementation. Until approval, no auth code enters the main line.
