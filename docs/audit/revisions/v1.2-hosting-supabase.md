**Trigger:** on 2026-10-26 the user supplied Supabase connection instructions and credentials for project `jefrozslozdrdwgbutgd` (ap-southeast-1).

| C-ID | Supersedes | Change |
|---|---|---|
| C-13 | "Neon" wherever it appears in v0, v1, v1.1 and artifacts 01, 06, 08, 10, 11 | Managed Postgres is **Supabase**. Runtime uses the Supavisor transaction pooler (port 6543, `pgbouncer=true`); CLI and migrations use the session pooler (port 5432) |
| C-14 | 06 §3 Pooling; T-RLS-009 | The design is unchanged: transaction-local `set_config` remains mandatory because 6543 is transaction mode. T-RLS-009 must run through **Supavisor 6543**, not only local PgBouncer |
| C-15 | 06 §3 RLS roles | Supabase ships `postgres`, `anon`, `authenticated` and `service_role`, and `postgres` and `service_role` bypass RLS. Add a dedicated `gems_app` login role (NOBYPASSRLS, not owner) for the runtime connection. **Do not run the app as `postgres`.** T-RLS-001 must also check that the Supabase Data API (PostgREST) cannot reach app tables: revoke `anon`/`authenticated` on the app schema, or disable the API |
| C-16 | 08 §6 "fresh Neon branch" | Dry runs use a separate Supabase project or branch (branching availability depends on plan, to confirm), never production |
| C-17 | 11 P2/P6 "Neon pooled endpoint" | Re-run on the Supabase transaction pooler |
