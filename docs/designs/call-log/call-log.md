## Overview

The front office keeps a log of phone calls that are not (yet) enquiries (R-084, SRC). Calls about a known enquiry are already its follow-ups (E-042).

This piece adds:
*   one append-only table, `app.call_log`;
*   its server functions in `src/server/call-log.ts`;
*   one page, `/calls`, with one save route.

It reuses:
*   the enquiry permissions;
*   the counsellor functions (tele-callers);
*   `phoneDigits`, `ownText`, `isoDate` and `istToday`;
*   the 0018 immutability triggers.

## Goals

*   **G1:** a holder of `enquiry.manage` at an active centre logs a call. Each field is validated with a field message; the database records who logged it and when; the call is audited [T-CL-001].
*   **G2:** a holder of `enquiry.view` lists the centre's calls, newest first, with filters. Nobody else can, also by SQL. The log cannot be changed or deleted, also by SQL [T-CL-001, T-CL-002].
*   **G3:** the page and route check the origin and give field errors. A malformed or out-of-scope centre gives a 404 [T-CL-003, smoke].

## Non-Goals

*   R-080 front-office masters (DD-5, deferred: PRO to confirm).
*   Editing or deleting a call (DD-3).
*   Turning a call into an enquiry automatically. The page links to "New enquiry" with no pre-filled values, because personal data does not go in URLs.
*   Call reports (Stage 7) and the legacy import (paused).

## Technical Plan (Architecture)

### Data model (migration `0022_call_log`)

The head of the migration is generated by `prisma migrate diff`. Prisma model `CallLog`; `Centre.callLogs`; `AppUser` gets two back-relations.

```
app.call_log (
  id bigserial primary key,
  centre_id int not null references app.centre(id) on delete restrict on update restrict,
  phone text not null, name text, called_on date not null,
  call_type text not null, duration_min int, description text, note text,
  next_follow_up_on date,
  tele_caller uuid references app.app_user(id) on delete restrict on update restrict,
  by_user uuid not null references app.app_user(id) on delete restrict on update restrict,
  at timestamptz not null default now()
)
index (centre_id, called_on desc, id desc); index (centre_id, phone)
```

**Named checks:**

| Check | Rule |
|---|---|
| `call_log_phone_check` | `phone ~ '^[0-9]{10}$'` |
| `call_log_name_check` | btrim, 1–100 |
| `call_log_call_type_check` | `in ('INCOMING', 'OUTGOING')` |
| `call_log_duration_min_check` | 0–600 (PMC) |
| `call_log_description_check`, `call_log_note_check` | The `ownText` multiline rule, 1–1000, using the 0018 `ws` / `ctl` constants in a do-block |
| `call_log_follow_up_check` | `next_follow_up_on >= called_on` |

**`call_log_guard`:** a BEFORE INSERT trigger with invoker rights and `set search_path = pg_catalog, app`, as `enquiry_followup_guard` does. It:
*   sets `by_user := coalesce(app.session_user_id(), new.by_user)`;
*   sets `at := now()`;
*   for `gems_app`, refuses with 23514 `call_log_tele_caller_guard` when `tele_caller` is set and `app.enquiry_may_receive(centre_id, tele_caller)` is false. The message carries `constraint "…"`, because the driver drops the constraint field (course-batches R1).

**Immutability:** `call_log_no_update_delete` (before update or delete) and `call_log_no_truncate` (before truncate) both execute `app.ticket_immutable()`, as 0018 does. `reset.sql` and the test fixtures disable and re-enable the no-truncate trigger around the truncate, as for `enquiry_followup`.

**RLS (`centre_id`; four commands for T-RLS-002):**
*   `select`: `centre_id = any ((select app.scoped_centre_ids('enquiry.view'))::int[])`.
*   `insert`: the same expression with `enquiry.manage`.
*   `update` and `delete`: `using (false)`. There is no grant for either, and the triggers refuse them as well.
*   ENABLE and FORCE.

**Grants:** `select, insert (centre_id, phone, name, called_on, call_type, duration_min, description, note, next_follow_up_on, tele_caller) on app.call_log`, plus `usage` on its sequence. No new permission; no `system_admin` change.

### Server (`src/server/call-log.ts`)

**Writes:**
*   They go through `scopedAction` with `action: "call.create", permission: "enquiry.manage"` and the centre. There is no step-up.
*   The id is taken first (`nextval`) in a pre-flight `withScope`, so it can be the audit target.
*   The callback runs the trading gate (`centreId: centre is not active`).
*   It then inserts with an explicit id, inside `callDb`. `callDb` maps:
    *   23514 `call_log_tele_caller_guard` to `teleCaller: inactive or unknown`;
    *   other 23514 to `invalid value`;
    *   42501 to `Forbidden`.

**Validation:**
*   Field rules run before any database access, as `RbacError("invalid", "<field>: <rule>")` (`bad`).
*   The tele-caller is also checked in the app, with `enquiry_may_receive`, to give the field message. The guard is the backstop.

**Reads:**
*   They use `withScope` and `authorize(tx, "enquiry.view", centreId)`. A refusal is `Forbidden`, which the page turns into a 404.
*   A `phone` filter first calls `limitSearch(tx)` (T-SEC-015).

```ts
type CallInput = { centreId: number; phone: string; name?: string | null; calledOn?: string | null; callType: "INCOMING" | "OUTGOING";
  durationMin?: number | null; description?: string | null; note?: string | null; nextFollowUpOn?: string | null; teleCaller?: string | null };
type CallRow = { id: string; phone: string; name: string | null; calledOn: string; callType: string; durationMin: number | null;
  description: string | null; note: string | null; nextFollowUpOn: string | null; teleCaller: string | null; byUser: string; at: string };
type CallFilter = { from?: string; to?: string; callType?: string; dueBy?: string; phone?: string };

logCall(session, input: CallInput): Promise<{ id: string }>;                                 // call.create
listCalls(session, centreId, f: CallFilter): Promise<{ rows: CallRow[]; truncated: boolean }>; // newest first, 200 max (PMC)
callCentres(session): Promise<{ id: number; code: string; name: string; active: boolean; canLog: boolean }[]>; // enquiry.view centres
```

**Field rules, in this order:**

| Field | Rule | Message |
|---|---|---|
| `centreId` | A safe integer ≥ 1 | `centreId: unknown` |
| `phone` | Required; `phoneDigits` | `phone: required`, `phone: 10 digits` |
| `name` | Optional; btrim, 1–100 (`geoName` when given) | `name: 1-100 characters` |
| `calledOn` | Optional (default `istToday()`); `isoDate`; not after today | `calledOn: YYYY-MM-DD`, `calledOn: not in the future` |
| `callType` | INCOMING or OUTGOING | `callType: one of the listed values` |
| `durationMin` | Optional; integer 0–600 | `durationMin: 0-600` |
| `description`, `note` | Optional; `ownText(…, 1000, multiline)` | The `ownText` messages |
| `nextFollowUpOn` | Optional; `isoDate`; not before `calledOn` | `nextFollowUpOn: not before calledOn` |
| `teleCaller` | Optional (default: the person logging, when they may receive enquiries there; else null); a UUID that `enquiry_may_receive` accepts | `teleCaller: inactive or unknown` |

**Audit:** `call.create`, target `call` / id, `after` the stored values. The phone and name are kept, as in enquiry rows: centre staff already see them in the log.

**Names:** `listCalls` returns `teleCaller` and `byUser` as display names, via `app.enquiry_counsellors` for the tele-caller and the session's own name. A by-user name that the caller cannot read shows as "Staff".

### Page and route

| Route | What |
|---|---|
| `/calls` | Centre picker (`callCentres`). A 404 when the list is empty; one centre redirects straight to it. |
| `/calls?centre=<id>[&from&to&type&due]` | The list with GET filters (dates and type only; no phone in the URL). Loggers at an active centre also get the log form and a tele-caller select (`enquiryCounsellors`). |
| (no phone search page) | The phone filter exists in `listCalls` (rate-limited) but not on the page yet: a phone in a GET URL is personal data (DD-4). |
| `POST /calls/save` | `adminPost`; fields `centreId, phone, name, calledOn, callType, durationMin, description, note, nextFollowUpOn, teleCaller` (`""` → null; `Number()` for the duration). Back `/calls?centre=<id>`; success `…&saved=1`. |

*   A malformed, unknown or out-of-scope centre gives `notFound()`.
*   An inactive centre shows "This centre is not active." and no form.
*   The home page links Calls when `callCentres` is not empty.
*   The enquiries page links Calls.

## Decisions

All five are recommended options under the standing instruction.

1.  **DD-1:** a general call log per centre, with the fields above.
2.  **DD-2:** reuse `enquiry.view` and `enquiry.manage`. No calls are logged at an inactive centre.
3.  **DD-3:** append-only.
4.  **DD-4:** a list with filters, newest first; the phone search is rate-limited (server only for now); a "New enquiry" link without pre-filled values.
5.  **DD-5:** R-080 masters are deferred (PRO to confirm, D-GAP-2).

## Alternatives Considered

*   **Calls as enquiries of a "call" type.** Rejected. Enquiries need a date of birth, a gender, a path and a course, which a caller often does not give.
*   **A new permission `call.log`.** Rejected. The same front-office people work enquiries, and a new key would mean a new grant for every role.
*   **Editable entries.** Rejected for an audit trail. A wrong entry is followed by a correcting one.

## Risks and Limits

*   **No phone search on the page yet.** A caller who rings back is found by date and type only, or as an enquiry once one is made.
*   **Tele-callers must hold `enquiry.manage` at the centre** (the enquiry rule).
*   **The log grows without bound.** The list is capped at 200 rows; older calls are found by date range.
